# Control Panel 1.0.18

Release validation date: 2026-10-17.

## Changes

- Deletion and NFS reclaim now follow the operator handbook literally: after the
  ordinary host `umount`, the backend enters each remaining holder's mount
  namespace and runs an ordinary `umount` there, then removes the LV.
  - The namespace step is a plain remote command,
    `nsenter -t <pid> -m umount <path>`, issued once per discovered holder mount
    (`NamespaceUnmountCmd`). Only the mount namespace is entered, so the host
    root stays in effect and the discovered mount path resolves inside that
    namespace. The command never forces and never unmounts lazily.
  - Removed from these paths: process identity pinning, entering the holder's
    container root, mount-ID checks, workload-allowlist authorization, and the
    `dmsetup` Open Count pre-check that previously had to report zero before
    `lvremove` was allowed to run.
  - The device scan stays, because it is the only source of the `<pid>`/`<path>`
    pair the namespace unmount needs. A failed scan still retains the volume.
  - A volume that something still holds is now refused by `lvremove` itself,
    which reports filesystem-in-use and retains the volume.
- Every discovered holder is attempted, so one failing unmount cannot leave
  another holder's copy mounted. Failures are collected and reported together as
  `namespace unmount failed; retain volume: ...`.
- Task step names change. `cleanup_namespace_mounts` becomes
  `unmount_namespace_holders`. On the pre-removal path,
  `resolve_device_holders_before_remove`, `cleanup_namespace_mounts_before_remove`
  and `verify_device_released_before_remove` collapse into
  `unmount_namespace_holders_before_remove`. The `verify_device_released` step is
  gone from the retry path, which is now `scan_namespace_holders` →
  `resolve_namespace_holders_for_retry` → `unmount_namespace_holders` →
  `verify_lv_identity_before_retry` → `lvremove_retry`, and still runs at most
  once and only for a confirmed filesystem-in-use error.
- A namespace unmount failure no longer isolates the worker on these paths. It is
  reported as a task error, and unmounts that already succeeded are not rolled
  back. The retained Python host-unmount helper keeps its uncertainty marker.
- The deletion confirmation dialog now lists the handbook order without the
  open-count step. The operator handbook, the namespace recovery guide, the chart
  README and the deploy README describe the simplified flow.
- Scope: `storage_delete_lv` and `storage_reclaim_nfs`, which share this handler.
  The resize flow keeps its own conservative checks, including its zero-open
  requirement.

## Validation and operational limitations

- Full Go tests, `go vet ./...`, and `go build ./...`.
- 67 Python parser/physical-protection tests, plus Ruff check and format checks.
- 60 frontend/deployment tests, including UI/Helm version consistency.
- `helm lint`, JavaScript syntax and whitespace checks.

Tests use fixtures and mocked process evidence. No real Worker volume was
deleted. The namespace unmount has not run on a real Linux host; isolated Linux
acceptance of namespace entry, busy mounts and holder enumeration remains
required, and mocked tests do not prove production behavior. A volume held by
something the scan cannot see is now discovered only when `lvremove` refuses it.

UI, Helm chart version and appVersion are 1.0.18. The independent browser-crypto
build tooling remains at 0.1.0. This source release does not publish an image or
OCI chart, or deploy to production. Development database and local plan files
are excluded from the release commit.
