# Control Panel 1.0.22

Release validation date: 2026-10-20.

## Changes

This release closes the three preconditions 1.0.21 listed as outside its scope.

- A worker without NFS tooling no longer fails the deletion. Removing the export
  entry is skipped when `/etc/exports` does not exist, and refreshing exports is
  skipped when `exportfs` is absent; a worker with nothing to revoke has no
  export cleanup to do. A real `sed` failure on an existing file stays fatal.
- Unmount detection no longer depends on the worker's locale. The host `umount`,
  the `nsenter` unmount and `lvremove` now run with `LC_ALL=C`, so the
  `target is busy`, `not mounted` and `filesystem in use` wordings this flow
  matches on are util-linux's own C-locale strings rather than whatever the
  worker is configured to print. `mountpoint not found` joins `not mounted` as an
  already-released path.
- The recovery-marker refusal now names the file and the exact way out. An
  existing `/run/control-panel-storage-recovery.uncertain` was previously
  reported only as "storage recovery state is uncertain"; the message now says
  what left it, what to confirm, and that removing the file (or rebooting the
  worker, since the marker lives in `/run`) clears it.

## Validation and operational limitations

- Full Go tests, `go vet ./...`, and `go build ./...`.
- 70 Python parser/physical-protection tests, plus Ruff check and format checks.
- 60 frontend/deployment tests, including UI/Helm version consistency.
- `helm lint`, Go format, JavaScript syntax and whitespace checks.

Tests use fixtures and mocked process evidence. No real Worker volume was
deleted. The locale and tool-availability changes are not observable from a
mocked runner, so isolated Linux acceptance still has to confirm them on a real
worker alongside namespace entry and busy mounts.

Two limits remain deliberate rather than fixed:

- An existing recovery marker still refuses storage commands. Nothing in the
  current deletion flow creates it and the in-memory quarantine is only set by
  the retired shared-host unmount path, so a marker in the field is residue from
  an older release, sitting in tmpfs and cleared by a reboot. Refusing destructive
  work while it exists remains the marker's purpose.
- The marker check is not narrowed to destructive commands. Deciding which
  commands may bypass it is a safety decision about a worker whose mount state is
  unconfirmed, so it is left as it is.

UI, Helm chart version and appVersion are 1.0.22. The independent browser-crypto
build tooling remains at 0.1.0. This source release does not publish an image or
OCI chart, or deploy to production. Development database and local plan files
are excluded from the release commit.
