# Control Panel 1.0.21

Release validation date: 2026-10-19.

## Changes

- A host `umount` that reports the target busy no longer ends the deletion. That
  is the handbook's own case: a holder still keeps its own copy of the mount, so
  the holder's copy is ordinarily unmounted inside its mount namespace and the
  host `umount` is retried. Handbook 8.2 now states the retry explicitly.
  - The holder release therefore runs before the final unmount check, not after
    it, which is the order the handbook already described and which the
    handbook deletion test already expected.
  - A retry that still fails stops and retains the volume, and now reports that
    the remaining user is a local user of the mount rather than the holder.
  - Any other host unmount failure, and any failure of the namespace unmount
    itself, still stops and retains the volume.
- A mount that another actor already released is no longer a failure. If either
  the host `umount` or the holder's `nsenter` unmount reports `not mounted`, the
  state this step exists to produce already holds, so the flow continues to
  `lvremove` instead of failing on a race.
- The holder lookup tolerates unreadable `/proc` evidence. A single unreadable
  `/proc/<pid>/task` entry used to fail the whole lookup, which is one of the two
  candidate causes of the task #54 failure. The delete lookup now skips it; the
  retained strict scan still fails closed.

## Validation and operational limitations

- Full Go tests, `go vet ./...`, and `go build ./...`.
- 70 Python parser/physical-protection tests, plus Ruff check and format checks.
- 60 frontend/deployment tests, including UI/Helm version consistency.
- `helm lint`, Go format, JavaScript syntax and whitespace checks.

Tests use fixtures and mocked process evidence. No real Worker volume was
deleted, and none of these paths has run on a real Linux host; isolated Linux
acceptance of namespace entry, busy mounts and holder enumeration remains
required. The two failure messages the flow now recognizes (`target is busy`,
`not mounted`) are matched from util-linux output, so a localized or unusually
different `umount` message would fall back to stopping and retaining the volume,
which is the safe direction.

Known remaining limits, unchanged by this release:

- A stale `/run/control-panel-storage-recovery.uncertain` marker on a worker
  refuses every storage command with exit 75. Nothing in the current delete flow
  creates that marker; only an interrupted legacy host-unmount helper can leave
  one, and clearing it is a manual, confirmed step.
- The `sed` on `/etc/exports` and `exportfs -arv` steps still require an
  `/etc/exports` and `exportfs`, so deleting a mounted LV on a worker without
  nfs-utils stops there. Provisioning uses the same tools, so a storage worker
  is expected to have them.

UI, Helm chart version and appVersion are 1.0.21. The independent browser-crypto
build tooling remains at 0.1.0. This source release does not publish an image or
OCI chart, or deploy to production. Development database and local plan files
are excluded from the release commit.
