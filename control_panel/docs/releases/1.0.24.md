# Control Panel 1.0.24

Release validation date: 2026-10-21.

## Changes

A grow that `lvextend -r` had already completed could still be reported as
failed.

- A mounted ext volume no longer repeats `resize2fs` unconditionally.
  `lvextend -r` performs the online grow, and the kernel writes the enlarged
  superblock asynchronously; the follow-up `resize2fs` issued immediately
  afterwards could read that superblock mid-update and refuse to open the
  filesystem (`Superblock checksum does not match superblock`), failing a task
  whose volume and filesystem had both grown. The completion step now compares
  the size the kernel reports for the mount (`stat -f`) with the enlarged device
  (`blockdev --getsize64`) and runs the handbook's `resize2fs` only when the
  filesystem still lags, or when the mount can no longer be measured.
- An unmounted ext volume still runs `resize2fs` directly, and a mounted XFS
  still completes with `xfs_growfs`. Neither has an online grow of its own in
  front of the completion command.
- A grow is still refused when the pinned LV identity or the filesystem type
  changes between the preflight and the recheck. Mount-target churn alone is not
  a refusal for grow, which is mount-agnostic; the recheck's fresh target is the
  one the completion uses.

## Validation and operational limitations

- Full Go tests, `go vet ./...`, and `go build ./...`.
- 70 Python parser/physical-protection tests, plus Ruff check and format checks.
- 60 frontend/deployment tests, including UI/Helm version consistency.
- `helm lint`, Go format, JavaScript syntax and whitespace checks.

The guarded resize shell, including the mounted-ext completion decision, is
executed by a POSIX shell in the fixture with `stat`, `blockdev`, `lvextend`,
`resize2fs` and `xfs_growfs` mocked, so the script's control flow is exercised
but no volume changes size. The kernel and e2fsprogs superblock timing this
release avoids cannot be reproduced locally; isolated Linux acceptance on a real
worker is still required. A mounted grow does not re-read the capacity on NFS
clients: a client that cached the share size sees the new size after remounting,
which is an operational step and not a panel guarantee.

UI, Helm chart version and appVersion are 1.0.24. The independent browser-crypto
build tooling remains at 0.1.0. This source release does not publish an image or
OCI chart, or deploy to production. Development database and local plan files
are excluded from the release commit.
