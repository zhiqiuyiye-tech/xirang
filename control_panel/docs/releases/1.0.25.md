# Control Panel 1.0.25

Release validation date: 2026-10-22.

## Changes

A grow no longer hands the filesystem work to fsadm, and a filesystem that
cannot be grown no longer hides the extension that already happened.

- The logical volume extension and the filesystem grow are two explicit
  commands. `lvextend -r` runs fsadm, whose `tune2fs` superblock read fails on
  some mounted ext volumes with `Superblock checksum does not match superblock`
  (e2fsprogs below 1.47 reads the superblock through the block-device page
  cache, which the kernel's asynchronous online-resize update can leave stale).
  When fsadm failed, the LV had already been extended but the task reported a
  bare failure, leaving a volume larger than its filesystem with no statement of
  that state.
- Grow now runs `lvextend -L +<step>G` and then grows the filesystem. A mounted
  ext volume is verified against the kernel's size first (`stat -f` versus
  `blockdev --getsize64`) and runs `resize2fs` only when the filesystem still
  lags; an unmounted ext volume runs `resize2fs` directly; a mounted XFS
  completes with `xfs_growfs`. An unmounted XFS keeps `lvextend -r`, because
  `xfs_growfs` cannot touch an unmounted filesystem.
- A failed filesystem grow now reports that the logical volume is extended and
  the filesystem is not, and names the command that completes it. The task still
  fails, because the filesystem really is not grown, but the message no longer
  reads like a lost resize.
- Shrink is unchanged: `lvreduce -y -r` still shrinks the filesystem first and
  aborts the reduce when it cannot, offline and ext-only.

## Validation and operational limitations

- Full Go tests, `go vet ./...`, and `go build ./...`.
- 70 Python parser/physical-protection tests, plus Ruff check and format checks.
- 60 frontend/deployment tests, including UI/Helm version consistency.
- `helm lint`, Go format, JavaScript syntax and whitespace checks.

The guarded resize shell is executed by a POSIX shell in the fixture with
`stat`, `blockdev`, `lvextend`, `resize2fs` and `xfs_growfs` mocked, so the
script's control flow is exercised but no volume changes size. The superblock
read behaviour of a mounted ext filesystem on a real worker cannot be reproduced
locally, so isolated Linux acceptance is still required. A worker whose
e2fsprogs cannot read a mounted ext superblock cannot complete an online
filesystem grow at all: unmount the volume (host and holder namespaces) and grow
the filesystem offline, and upgrade e2fsprogs before relying on online grows
there again.

UI, Helm chart version and appVersion are 1.0.25. The independent browser-crypto
build tooling remains at 0.1.0. This source release does not publish an image or
OCI chart, or deploy to production. Development database and local plan files
are excluded from the release commit.
