# Control Panel 1.0.14

Release validation date: 2026-10-13.

## Changes

- Use extension-only `.pem` filters for administrator key login, enrollment and
  rotation to avoid Windows browser MIME-type expansion when opening the native
  file picker. Preserve local-only private-key handling, size limits, key-format
  checks, fingerprint matching and challenge signatures.
- Cache Worker GPU/NPU hardware discovery by SSH connection configuration and
  encrypted-credential fingerprint. Ordinary page visits and Worker heartbeats
  reuse hardware samples; new or changed Workers and explicit refresh collect
  new samples. Concurrent ordinary requests share probes, deleted Workers are
  removed, and failed/partial probes become retryable after 30 seconds.
- Maintain a display-only Kubernetes Pod/Node list/watch cache for accelerator
  allocation snapshots. Workload and Node changes invalidate allocations without
  listing the cluster for each Worker page visit. Continue counting all bound
  non-terminal workloads, not only Notebooks. Initial unsynchronized allocations
  remain unknown; watch reconnects provide eventual consistency. Storage safety
  and authorization checks do not use this cache. No additional RBAC is required.
- Offer eligible unmounted disks and partitions with recognized single-device
  filesystem signatures for VG initialization. Revalidate all selected devices
  before mutation and repeat the live preflight immediately before clearing
  signatures, followed by non-forced `pvcreate` and per-device `vgcreate`.
- Continue rejecting mounted or protected devices, whole disks with children,
  partition-table, LVM, RAID, encrypted, swap, unknown and Btrfs signatures.
  Btrfs members require a separate multi-device safety assessment and are not
  automatically reinitialized.
- Accept valid Linux `nsfs` namespace handles in unrelated mountinfo root
  records during NFS namespace recovery. Continue requiring canonical absolute
  paths for target LV roots and mountpoints, and retain topology protections.
- Require explicit disk selection in the VG initialization dialog and clearly
  warn that existing filesystem data will be lost. An unmounted filesystem is
  not evidence that its data can be discarded.

## Validation

- Full Go tests, `go vet ./...` and `go build ./...`.
- Browser regression tests, JavaScript syntax checks and asset build.
- Repeated hardware-cache concurrency and Kubernetes watch-update tests.
- Generated device-preflight shell fixtures and mocked storage handlers; no
  real Worker SSH connection or disk mutation is used during validation.
- Helm lint and release-version consistency checks for UI, Chart and packaging
  documentation.

Windows native file-picker latency and live Worker/cluster acceptance still
require operator confirmation after deployment. No Docker image publication or
production deployment is implied by this source release. CGO race testing is
unavailable in the current Windows environment; no race-detector result is claimed.

UI, Helm chart version and appVersion are 1.0.14. The private browser-crypto build
package remains at its independent tooling version 0.1.0. No database migration
or development-database update is part of this release.
