# Control Panel 1.0.20

Release validation date: 2026-10-19.

## Changes

- The holder lookup before `lvremove` now returns only what the handbook unmount
  consumes: the task to enter and the paths to ordinarily unmount inside its
  mount namespace. It answers the question the flow actually asks - which
  process still holds the device - instead of collecting namespace membership
  evidence that deletion stopped using.
  - It matches the target device's major:minor in `/proc/<pid>/mountinfo`. The
    reported PID is the lowest task ID of the mount namespace, which is the
    thread group leader of a container process: the PID an operator recognizes
    on the node.
  - A task whose evidence cannot be read, and a mount that fails the protection
    checks, are skipped individually instead of failing the whole lookup. A
    skipped task can only cost one refused removal, because lvremove refuses a
    volume that any namespace still holds, and a returned path was proven to be
    this device at that path.
  - Dropped from this lookup: cgroup and start-time identity, complete namespace
    membership sets, root-inode agreement between namespace members, and the
    per-task namespace and root probes. Those existed to authorize entering a
    pinned container root, which the handbook flow no longer does.
  - `scan_delete` now answers with `{"device": ..., "holders": [{"pid": ...,
    "paths": [...]}]}`. The retained strict scan keeps its own `scan` operation
    and its fail-closed evidence chain.
- A lookup failure still does not block the delete, and a lookup that reports a
  different device identity is still fatal, as introduced in 1.0.19.

## Validation and operational limitations

- Full Go tests, `go vet ./...`, and `go build ./...`.
- 70 Python parser/physical-protection tests, plus Ruff check and format checks.
- 60 frontend/deployment tests, including UI/Helm version consistency.
- `helm lint`, JavaScript syntax and whitespace checks.

Tests use fixtures and mocked process evidence. No real Worker volume was
deleted. The change has not run on a real Linux host; isolated Linux acceptance
of namespace entry, busy mounts and holder enumeration remains required, and
mocked tests do not prove production behavior. Expected on the first real run:
the unmount list is shorter than before, because mounts that fail the protection
checks are now excluded rather than refusing the lookup.

The cause of the task #54 lookup failure is still unidentified. 1.0.19's message
change is what will name it, and this release makes the lookup both narrower and
far less likely to fail.

UI, Helm chart version and appVersion are 1.0.20. The independent browser-crypto
build tooling remains at 0.1.0. This source release does not publish an image or
OCI chart, or deploy to production. Development database and local plan files
are excluded from the release commit.
