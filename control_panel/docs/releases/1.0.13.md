# Control Panel 1.0.13

Release validation date: 2026-10-12.

## Changes

- Harden LV resizing with live mount/fstab, protected/reserved path, swap,
  device-open and Pod-use checks, repeated identity verification, and fail-closed
  uncertainty handling. Preserve the guarded NFS reclaim exception.
- Add an explicit non-NFS CSI driver configuration list. Unknown CSI and
  incomplete NFS CSI sources still stop destructive reclaim.
- Keep target identity and UID/resource-version checks for Service and
  NetworkPolicy operations; reject a selector that currently matches multiple
  Pods. Preserve rollback outcomes and cleanup context budgets.
- Bound task admission/execution and queued-task timeouts; improve SSH budget
  propagation, worker health checks, inventory refresh scheduling, and audit
  parameter filtering.
- Remove platform-registration SQL generation/display/copy while retaining NFS
  fields and durable registration/reclaim snapshots.
- Add configurable history retention: ordinary terminal tasks/steps 90 days and
  audits 365 days; preserve successful NFS provision rows and their parameters.
  Use bounded transactions, UTC cutoff indexes, hourly/time-budgeted cleanup,
  cancellation/join on shutdown, and validated deployment settings.
- Add 1k/10k Kubernetes display benchmarks and request-local reference indexes
  and parsed-inventory reuse. Local allocations are about 5 MB lower per 10k mount
  request. No production latency improvement or cross-request safety cache is
  claimed.
- Correct the inventory-refresh test fixture by injecting its collector; the
  production HTTP 503 failure behavior is unchanged.
- Align AES Secret encoding for Helm and deployment and record confirmed
  shared-account/cross-namespace and credential-scan boundaries.

## Validation

Go package tests with coverage, Go static analysis, browser build and tests,
Helm rendering/lint, Python namespace-recovery parser/safety tests, repeated
queue/SSH/collector/retention lifecycle tests, and complete generated resize
shell-probe tests using isolated fixture inputs are part of release validation.

The fixture shell tests mock device type and command outputs and never access
real Worker storage. A live Linux Worker/cluster acceptance test is still an
operator deployment task. Docker and CGO race testing are unavailable in this
Windows validation environment; no race-detector result is claimed.

The owner chose to retain one shared administrator and cluster-wide namespace
management. These limitations are documented rather than described as fixed.
Local redacted scans matched only owner-confirmed synthetic test/template values;
no operational credential revocation, production key rotation or history rewrite
was performed.

UI, Helm chart version and appVersion are 1.0.13. The private 0.1.0 browser-crypto
build package has its own tooling version and is not the application release.
