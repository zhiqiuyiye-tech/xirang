# Control Panel 1.0.17

Release validation date: 2026-10-16.

## Changes

- Fix virtual volume deletion stopping at `scan_namespace_holders_before_remove`
  with `remote scan_delete failed: process/thread scale exceeds limit`.
  - The host scan aborted once the total number of live tasks exceeded a fixed
    `MAX_PROCESSES = 32768` constant, so the pre-`lvremove` release step refused
    and retained the volume on any worker with more threads than that constant.
  - The task bound now follows the host's own `/proc/sys/kernel/pid_max`, the
    kernel ceiling for live tasks in that PID namespace, so a legitimate worker is
    never refused for its thread count. The failure text now reports the observed
    count and the limit.
  - Deletion scans read one `mountinfo` per (mount namespace, task root) view
    instead of one per thread. That pair fixes the whole output of a task's
    `mountinfo`, so the resulting holder set is unchanged while the cost scales
    with namespaces instead of the host's thread count, which keeps the step
    inside the remote 60-second budget.
  - A task that moves between two views during the read stays fatal, so a cached
    verdict never describes a view that was not read.
- Scope: `scan_delete` and `verify_delete`, the handbook deletion flow. The resize
  scan keeps its original per-task behavior.

## Validation and operational limitations

- Full Go tests, `go vet ./...`, and `go build ./...`.
- 67 Python parser/physical-protection tests, plus Ruff check and format checks.
- 60 frontend/deployment tests, including UI/Helm version consistency.
- JavaScript syntax and whitespace checks.

Tests use fixtures and mocked process evidence. No real Worker volume was deleted.
The changed scan logic has not run on a real Linux host; isolated Linux acceptance
of namespace/root handling, propagation, busy mounts and helper termination
remains required, and mocked tests do not prove production behavior.

Unchanged limits: the snapshot validator still rejects a single holder namespace
carrying more than 32768 members, and the resize scan still reads `mountinfo` once
per task.

UI, Helm chart version and appVersion are 1.0.17. The independent browser-crypto
build tooling remains at 0.1.0. This source release does not publish an image or
OCI chart, or deploy to production. Development database and local plan files
are excluded from the release commit.
