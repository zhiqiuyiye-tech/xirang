# Control Panel 1.0.19

Release validation date: 2026-10-19.

## Changes

- The residual-holder lookup before the first `lvremove` no longer blocks the
  handbook delete. It exists only to supply the `<pid>` and `<path>` that the
  handbook unmount needs, so a host whose process evidence cannot be read now
  skips that unmount, records the reason on the step, and continues to
  `lvremove` instead of retaining the volume.
  - Nothing is destroyed earlier than before: `lvremove` still refuses a volume
    that any namespace or process holds, and retains it. A host that cannot be
    read only loses the automatic unmount, which the operator can repeat by hand
    with the handbook command.
  - A lookup that succeeds but reports a different device identity stays fatal.
    Its holders belong to another volume, so unmounting them would change the
    wrong namespace.
  - A failed ordinary unmount in a holder's mount namespace stays fatal, as
    before: that is the handbook step itself, not the lookup.
- The host helper's unexpected-failure message now names the real cause. It
  previously replaced every unexpected exception with the fixed text
  "host recovery probe or evidence failed" and printed nothing, so a defect, an
  unreadable `/proc` entry and a decoding failure were indistinguishable in the
  task log. The response keeps its exact three-key contract, and the traceback
  goes to stderr for manual runs.

## Validation and operational limitations

- Full Go tests, `go vet ./...`, and `go build ./...`.
- 67 Python parser/physical-protection tests, plus Ruff check and format checks.
- 60 frontend/deployment tests, including UI/Helm version consistency.
- `helm lint`, JavaScript syntax and whitespace checks.

Tests use fixtures and mocked process evidence. No real Worker volume was
deleted. The change has not run on a real Linux host; isolated Linux acceptance
of namespace entry, busy mounts and holder enumeration remains required, and
mocked tests do not prove production behavior.

The failure that motivated this release was reported as task #54 on worker 2:
`namespace scan failed before removal; retaining volume: remote scan_delete
failed: host recovery probe or evidence failed`, on a volume that `detect_mount`
reported as not mounted. The cause of that specific lookup failure is still
unknown; the message change above is what will identify it on the next attempt.

UI, Helm chart version and appVersion are 1.0.19. The independent browser-crypto
build tooling remains at 0.1.0. This source release does not publish an image or
OCI chart, or deploy to production. Development database and local plan files
are excluded from the release commit.
