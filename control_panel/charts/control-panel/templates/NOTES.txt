Control panel is deploying to namespace '{{ .Release.Namespace }}'.

1. Wait for the pod to become Ready:

   kubectl -n {{ .Release.Namespace }} rollout status deployment/control-panel

2. Retrieve the bootstrap/recovery password from the Secret (username: admin):

   kubectl -n {{ .Release.Namespace }} get secret control-panel-secrets \
     -o jsonpath='{.data.ADMIN_INIT_PASSWORD}' | base64 -d ; echo

{{- if eq .Values.service.type "NodePort" }}
3. Access the web UI via NodePort ({{ .Values.service.nodePort }}):

   http://<any-node-ip>:{{ .Values.service.nodePort }}/

{{- else }}
3. Access the web UI via the Service ClusterIP:

   kubectl -n {{ .Release.Namespace }} port-forward svc/control-panel 8080:{{ .Values.service.port }}
   then open http://localhost:8080/

{{- end }}

First-time login: use the retrieved bootstrap password once to generate and
register a shared P-256 private-key file. Re-select the downloaded PEM to verify
it, then distribute the same file to authorized operators over a controlled
channel. Subsequent sign-ins use the private-key file only. All Worker, K8s,
and NFS operations are available to every holder of that shared key.

Notes:
- AES_KEY/JWT_SECRET/bootstrap-recovery secret are generated once on first install
  and reused across `helm upgrade`. Keep ADMIN_INIT_PASSWORD for operator recovery;
  it is not a fallback login once a public key is active. Changing secrets.adminPassword
  alone does not replace the active key or reset the database auth state.
- The pod pulls {{ .Values.image.repository }}:{{ .Values.image.tag }} with
  imagePullPolicy: {{ .Values.image.pullPolicy }}. Ensure cluster nodes can reach
  the registry; if it needs auth, set image.imagePullSecrets in values.
